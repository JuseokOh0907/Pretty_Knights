# 002. 스프라이트 파이프라인 — Codex 생성 → Aseprite 슬라이싱 → Aseprite Importer

- **상태:** 방향 확정, 착수 보류 (선행 조건 대기)
- **결정일:** 2026-08-01

## 배경

Unity 프로젝트에 **Aseprite Importer 가 설치되어 있다.** 이 임포터를 쓰면 `.aseprite` 원본을
Unity가 직접 읽어 레이어·프레임·태그를 스프라이트와 애니메이션 클립으로 자동 변환할 수 있다.
PNG 시트를 수동으로 슬라이싱하고 클립을 손으로 만드는 현재 방식보다 훨씬 싸다.

**그러나 `.aseprite` 원본 파일은 현재 하나도 없다.**
아트 작업이 Aseprite가 아니라 **Codex 에서 이미지 생성 방식으로 진행되고 있기 때문이다.**
따라서 지금 시점에 Aseprite Importer 로 전환할 수 없다.

## 결정

**Aseprite Importer 전환은 하되, 지금이 아니라 Discord 에이전트 오케스트라 설정이 완료된 뒤에 한다.**

전환 시점에 다음 자동화 스킬을 만든다.

### 목표 파이프라인

```
Codex (아트 생성)
  └─ 이어진 애니메이션 시트 + 개별 이미지를 파일별로 저장, 저장 경로를 전달
       ↓
Hermes Agent (Aseprite 조작)
  └─ 전달받은 경로의 이미지를 Aseprite에서 열어 픽셀 단위로 슬라이싱
     프레임·레이어·태그를 규약대로 구성해 .aseprite 로 저장
       ↓
Unity Aseprite Importer
  └─ .aseprite 를 그대로 임포트 → 스프라이트 + 애니메이션 클립 자동 생성
```

## 이유

- Codex 산출물은 PNG 이미지이지 `.aseprite` 가 아니므로, 둘 사이를 잇는 변환 단계가 반드시 필요하다.
- 그 변환(픽셀 단위 슬라이싱, 프레임 구성)은 Aseprite를 직접 조작하는 에이전트가 수행하면 자동화 가능하다.
- 자동화가 붙으면 신규 동작 1세트 추가 비용(`방향 × 동작 × 프레임`)이 사람 손에서 떨어진다.

## 선행 조건

- **Discord 에이전트 오케스트라 설정 완료** ← 이것이 끝나기 전에는 착수하지 않는다.
- Hermes Agent 의 Aseprite 조작 경로 확보

## 그때까지의 방침

- 현재 아트는 **PNG 시트 수동 슬라이싱**으로 계속 처리한다.
- Codex 로 새 아트를 만들 때도 `CLAUDE.md` §4 의 8방향 명명 규칙
  (`{순번}_{방향}_{동작}_{프레임레이아웃}.png`) 과 캔버스·피벗 규약을 **지금부터 지킨다.**
  나중에 Aseprite 단계를 끼워 넣을 때 규약이 이미 맞아 있으면 재작업이 없다.

## 미해결

- Hermes Agent 가 Aseprite 를 조작하는 방식 (Aseprite Lua 스크립트 / CLI / GUI 자동화)
- 레이어 분리(장비 교체용 Base body → Weapon 등)를 Codex 단계에서 할지 Aseprite 단계에서 할지
- 애니메이션 태그 명명 규약 (`.aseprite` 태그명이 곧 Unity 클립명이 된다)
