# 다시 밟지 않을 함정

> 한 번 겪었고, 원인을 찾는 데 시간이 걸렸고, **증상만 봐서는 원인을 알 수 없던** 것들.
> 새로 밟을 때마다 여기 한 항목씩 추가한다.
> 각 항목은 **증상 → 원인 → 규칙** 순으로 쓴다. 증상부터 쓰는 이유는
> 다음에 만날 때 손에 쥔 것이 증상뿐이기 때문이다.

## 씬 · 에셋

### `AreaDefinition` 이 비면 그 구역은 없는 것과 같다

**증상** — 포탈의 목적지를 제대로 채웠는데 이동이 안 된다. 디버그 이동으로도 못 간다.

**원인** — `AreaRegistry` 는 `AreaAnchor.definition` 이 비어 있으면 **등록조차 하지 않는다.**
등록되지 않은 구역은 번호로 찾을 수 없으므로 포탈도 디버그 이동도 도달하지 못한다.

**규칙** — 층을 만들면 `AreaDefinition` 부터 연결한다.
지금은 시작할 때 `[AreaRegistry] AreaDefinition 이 비어 등록되지 않은 구역이 N개` 경고가 뜬다 (커밋 `c01de66`).
`Pretty Knights > Areas > 0. 포탈 링크 점검` 이 재생 전에 잡아준다.

### 프리팹은 자식만 옮기면 콜라이더가 안 따라온다

**증상** — 포탈 위에 섰는데 사용 버튼이 안 뜬다. 또는 아무것도 없는 자리에서 버튼이 뜬다.

**원인** — 프리팹 인스턴스의 `Visual` 자식만 움직였다. 그림은 옮겨졌지만
`BoxCollider2D` 는 루트에 있어 원래 자리에 남는다.

**규칙** — **루트를 옮긴다.** 자식 Transform 은 프리팹이 정한 오프셋이므로 배치용이 아니다.

### 화면에서 사라진 것은 대개 "지워진 것" 이 아니라 "카메라 경계 밖" 이다

**증상** — 모드를 세로로 갔다가 가로로 돌아오면 플레이어가 안 보인다. 맵 사이에 낀 것처럼 보인다.

**원인** — 두 겹이었다.

1. `WorldLocation` 이 `(모드, 좌표)` 를 **한 슬롯**에 담고 있었다.
   세로에서 전환 버튼을 누르는 순간 `Set(Vertical, …)` 이 **가로 좌표를 덮어썼다.**
2. 돌아왔을 때 `Location.Mode != mode` 라 복원 함수가 **첫 줄에서 return** 했는데,
   구역 활성화가 그 안에 함께 있어 **구역도 안 켜졌다.**

그 결과 몸은 씬에 적힌 기본 위치(`Ingame_Horizontal` 은 `(39, 472)`)에 남았다.
Goblin1F 바닥은 `y −78~83` 이라 400 유닛쯤 밖이고,
**카메라는 활성 층 경계에 묶여 있어** 그쪽으로 따라가지 못한다. 그래서 사라져 보인다.

**규칙** — 셋이다.

- **모드마다 자리를 따로 든다.** 두 씬은 좌표계가 전혀 달라 한쪽 값을 다른 쪽에 쓸 수 없다
- **구역 활성화를 좌표 복원과 묶지 않는다.** 좌표가 없어도 구역은 맞춰야 한다
- **설 자리를 못 찾으면 포기하지 말고 도착 지점으로 보낸다.** 그냥 두면 벽에 낀 채로 남는다

> 안 보이는 것을 볼 때 **몸이 없는 것과 몸이 화면 밖인 것을 먼저 갈라야 한다.**
> 하이어라키에서 `Player` 를 선택해 Transform 을 보면 1초에 판별된다.

### 도착 지점 이름은 "어디서 왔는가" 다

**증상** — 이름만 봐서는 어느 포탈이 그리로 오는지 읽을 수 없다.

**원인** — 도착 지점을 "여기가 어디인가" 로 이름 지으면 층마다 이름이 같아진다.

**규칙** — `ArrivalPoint.arrivalId` 는 **출발지**를 가리킨다.
던전 입구에 내려서는 사람은 보상방에서 온 것이므로 `from_reward` 다.
`from_entrance` 로 지으면 반대로 읽힌다.

## 타일맵

### `Tile` 의 기본 `flags` 가 `LockColor` 라 `SetColor` 가 조용히 무시된다

**증상** — 벽을 때렸는데 손상 표시(색)가 전혀 안 바뀐다. **에러도 경고도 없다.**

**원인** — `TileBase` 의 기본 `TileFlags` 에 `LockColor` 가 들어 있다.
잠긴 채로 `Tilemap.SetColor` 를 부르면 아무 일도 일어나지 않고 로그도 남지 않는다.

**규칙** — `SetColor` 앞에 반드시

```csharp
tilemap.SetTileFlags(cell, TileFlags.None);
tilemap.SetColor(cell, damagedColor);
```

### Breakable 타일이 `Guide` 와 같은 칸에 겹치면 부숴도 안 뚫린다

**증상** — 벽을 부쉈고 그림도 사라졌는데 지나갈 수 없다.

**원인** — 같은 칸에 `Guide` 타일이 남아 있어 콜라이더가 그대로다.

**규칙** — Breakable 을 그린 칸은 `Guide` 에서 비운다.
Sorting Order 는 `Guide` 보다 **1 높게** (같으면 프레임마다 그리기 순서가 뒤집혀 깜빡인다).

## 코드

### 인터페이스 참조에는 Unity 의 널 비교가 걸리지 않는다

**증상** — 이미 파괴된 대상에 데미지를 넣다가 `MissingReferenceException`.
`if (target != null)` 로 막았는데도 통과한다.

**원인** — `UnityEngine.Object` 의 `==` 오버로드는 **`UnityEngine.Object` 타입일 때만** 동작한다.
`IDamageable` 같은 인터페이스로 들고 있으면 C# 기본 참조 비교가 쓰여
"파괴됐지만 관리 객체는 살아 있는" 상태를 걸러내지 못한다.

**규칙** — 캐스팅해서 비교한다.

```csharp
if (target is UnityEngine.Object o && o == null) continue;
```

### 판정 코어에 상태를 두지 않는다

**증상** — 보스와 잡몹이 같은 프레임에 공격하면 한쪽 판정 결과가 섞인다.

**원인** — 정적 `List` 하나를 결과 버퍼로 재사용하면 중첩 호출에서 덮어쓴다.

**규칙** — `SkillShape` 는 무상태다. 결과 버퍼는 호출자가 넘기고,
"이미 맞힌 대상" 은 시전마다 하나인 `SkillInstance` 가 든다.
