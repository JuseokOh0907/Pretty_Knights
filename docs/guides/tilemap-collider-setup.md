# 타일맵 콜라이더 설정 가이드

> 벽은 막고 바닥은 통과시키는 구성. 모바일 물리 비용까지 고려한 절차서.

---

## 1. 두 가지가 함께 있어야 한다

| | 어디에 | 역할 |
|---|---|---|
| **`Collider Type`** | **Tile 에셋** (`.asset` 파일) | 이 타일이 충돌을 만들지, 어떤 모양으로 만들지 |
| **`TilemapCollider2D`** | Tilemap **게임오브젝트의 컴포넌트** | 실제 물리 형상을 생성하는 주체 |

`TilemapCollider2D` 가 칸마다 놓인 타일의 `Collider Type` 을 읽어 형상을 만든다.

- 컴포넌트 없이 Tile 에셋만 `Sprite` 로 두면 → **아무것도 안 막힌다**
- 컴포넌트만 붙이고 타일이 전부 `None` 이면 → **아무것도 안 막힌다**
- 컴포넌트 + 타일이 `Sprite`/`Grid` → 막힌다

## 2. Collider Type 세 가지

Tile 에셋을 Project 창에서 선택하면 인스펙터에 나온다.

| 값 | 동작 | 쓰는 곳 |
|---|---|---|
| **None** | 충돌 없음 | **바닥, 장식** |
| **Sprite** | 스프라이트의 알파 외곽선을 따라감 | 모양이 불규칙한 프롭 |
| **Grid** | 칸 전체를 꽉 찬 사각형으로 | **벽** |

**`Sprite` 는 오류가 아니다.** 정상 동작하며, 벽 타일이 여백 없이 꽉 찬
불투명 사각형이면 `Grid` 와 사실상 같은 결과가 나온다.

그래도 **벽은 `Grid` 를 권한다.** 차이가 드러나는 경우가 둘 있다.

- **벽 그림에 투명 여백이 있을 때** — 콜라이더가 칸 경계보다 안쪽으로 들어와
  벽에 붙어 걸을 때 살짝 파고들어 보인다
- **`CompositeCollider2D` 와 함께 쓸 때** — 인접 타일의 외곽선이 칸 경계에서
  정확히 일치하지 않으면 합쳐지지 않고 미세한 내부 모서리가 남는다.
  벽을 따라 걷다 여기에 걸린다

`Grid` 는 항상 칸 경계에 맞아 이 문제가 없고 정점도 4개뿐이다.
`Sprite` 로 두고 진행하다 벽에 걸리는 느낌이 나면 그때 바꿔도 된다 —
바꿔도 다른 설정은 건드릴 필요가 없다.

> 스프라이트를 타일맵에 끌어다 만든 타일은 기본값이 `Sprite` 다.
> 그 상태의 바닥 타일이 **콜라이더 컴포넌트가 붙은 레이어**에 깔리면
> 바닥 전체가 벽이 된다. 이게 "투명벽" 증상의 정체다.
> 조건이 둘 다 맞아야 생기므로, 바닥 레이어에 컴포넌트를 안 붙이는 것만으로도 막힌다.

## 3. 레이어 구조

```
Grid
├─ Field   (Tilemap + TilemapRenderer)                 바닥 — 타일 Collider Type: None
├─ Guide   (Tilemap + TilemapRenderer                  벽 — 타일 Collider Type: Grid
│           + TilemapCollider2D
│           + Rigidbody2D  [Body Type: Static]
│           + CompositeCollider2D)
└─ Deco    (Tilemap + TilemapRenderer)                 장식 — None
```

`TilemapCollider2D` 는 **벽(Guide) 레이어에만** 붙인다.

> 바닥(Field)에 `TilemapCollider2D` 가 없으면 **Field 타일의 Collider Type 은
> 아예 읽히지 않는다.** 그러니 바닥 타일 설정은 뭘로 두든 무관하며 굳이
> `None` 으로 바꾸러 다닐 필요가 없다.
> 반대로 말하면, 바닥이 막히는 증상은 바닥 레이어에 콜라이더 컴포넌트가
> 붙어 있다는 뜻이다.

## 4. CompositeCollider2D — 모바일에서 이게 핵심

`TilemapCollider2D` 만 쓰면 **타일 한 칸마다 콜라이더 형상이 하나씩** 생긴다.
18 × 10 맵이면 벽만 해도 수십 개, 지역이 커지면 수백 개가 된다.
모바일에서 물리 갱신 비용이 여기서 붙는다.

`CompositeCollider2D` 를 얹으면 **맞닿은 타일들이 하나의 큰 폴리곤으로 합쳐진다.**
벽 한 줄이 형상 1개가 된다.

### 붙이는 순서

1. 벽 Tilemap 오브젝트 선택
2. `TilemapCollider2D` 추가
3. `CompositeCollider2D` 추가
   → `Rigidbody2D` 가 **자동으로 함께 붙는다**
4. 그 `Rigidbody2D` 의 **Body Type 을 `Static`** 으로 바꾼다
   (기본값 Dynamic 이면 벽이 물리로 밀려 떠내려간다)
5. `TilemapCollider2D` 의 **`Composite Operation` 을 `Merge`** 로
   → 이걸 `None` 으로 두면 합쳐지지 않고 두 컴포넌트가 따로 논다
6. `CompositeCollider2D` 의 `Geometry Type` 은 `Outlines` 로 둔다

### `Composite Operation` 선택지

Unity 6 에서 옛 `Used By Composite` **체크박스가 이 드롭다운으로 바뀌었다.**
체크박스 시절의 "켬"이 `Merge` 다.

| 값 | 동작 | 쓰임 |
|---|---|---|
| `None` | 참여 안 함 (= 옛 체크 해제) | 기본값 |
| **`Merge`** | **합집합. 맞닿은 형상이 하나로 합쳐진다** | **벽** |
| `Intersect` | 교집합 | 특수 |
| `Difference` | 이 콜라이더만큼 빼낸다 | 벽에 구멍 뚫기 |
| `Flip` | 안팎 반전 | 특수 |

### `Geometry Type`

- **`Outlines`** (기본값) — 외곽선만. 벽 막기에는 충분하다
- `Polygons` — 속이 찬 다각형. 벽 **안쪽에 생성된 오브젝트를 밀어내야 할 때**

몬스터 스폰이 벽과 겹칠 가능성이 생기면 그때 `Polygons` 로 바꾼다.

### 확인

Scene 뷰에서 벽을 보면 초록 외곽선이 **칸마다 격자로 보이면 실패**,
**벽 덩어리 바깥쪽만 한 줄로 감싸면 성공**이다.

## 5. 자주 걸리는 것

| 증상 | 원인 |
|---|---|
| 캐릭터가 아예 못 움직임 (투명벽) | 바닥 레이어에 `TilemapCollider2D` 가 붙어 있고 그 타일이 `Sprite`/`Grid` |
| 벽 레이어인데 안 막힘 | 컴포넌트는 있는데 타일이 `None`, 또는 그 반대 |
| 벽이 밀려서 떠내려감 | `CompositeCollider2D` 가 붙인 `Rigidbody2D` 가 Dynamic |
| 합쳐지지 않고 칸마다 콜라이더 | `Composite Operation` 이 `None` |
| 벽 모서리에 걸림 | 벽 타일이 `Sprite` — `Grid` 로 바꾼다 |
| 타일을 지웠는데 충돌이 남음 | 재생 중 변경. 정지 후 다시 확인 |

## 6. 모서리 타일(TL / TR / BL / BR) 문제

9슬라이스 모서리 타일은 `Sprite` 도 `Grid` 도 그대로는 맞지 않는다.

| | 결과 | 왜 |
|---|---|---|
| `Sprite` | **삼각형 콜라이더** | Unity 가 알파 외곽선을 자동 생성할 때 단순화 허용치를 적용해 L자 안쪽 꺾임이 대각선으로 펴진다 |
| `Grid` | **칸 전체가 막힘** | 정상 동작이지만 모서리 안쪽에 바닥처럼 보이는 영역이 있으면 "보이는데 못 가는 칸"이 된다 |

### A. Custom Physics Shape 를 직접 그린다

`Collider Type` 은 `Sprite` 로 두고 자동 외곽선 대신 모양을 손으로 지정한다.

1. 모서리 타일 PNG 선택 → 인스펙터의 **Sprite Editor** 버튼
2. 좌상단 드롭다운을 **`Custom Physics Shape`** 로 변경
3. 빈 영역을 드래그해 경로 생성, 정점을 끌어 정확한 L자로 맞춘다
   (경로를 2개로 나눠 직각 사각형 두 개로 만들어도 된다)
4. **Apply**

자동 단순화를 거치지 않으므로 삼각형이 나오지 않고, `Merge` 와도 잘 합쳐진다.
단점은 **수치 입력이 없어 눈대중**이라는 것과 테마마다 반복해야 한다는 것
(Base 3종 + Goblin/Orc/Vampire = 6세트 × 4모서리 = 24장).

### B. 충돌 전용 타일맵 분리

`Collision` 레이어를 만들어 단순 사각형 타일 하나로 충돌만 칠하고
`TilemapRenderer` 를 끈다. 아트와 충돌이 완전히 분리된다.
테마가 늘어날수록 A 보다 유리하다 — 타일 에셋을 손보는 대신 맵마다 충돌만 칠한다.
여전히 칸 단위라 모서리를 반만 막을 수는 없다.

### C. 레벨 디자인으로 우회

`Grid` 를 그대로 쓰되 **벽 링 전체를 못 가는 영역으로 놓고
바닥을 한 칸 안쪽부터 시작**하도록 방을 그린다.
콜라이더를 전혀 손대지 않는 유일한 방법이고, 대부분의 탑다운 게임이 이렇게 한다.

### 판단 기준 (2026-08-01 시점)

**미결정 #2(카메라·타일 투영·충돌·가림 규칙)가 확정되기 전에는 C 로 둔다.**
지금 A 로 24장을 손보면 #2 가 B 방향으로 확정될 경우 그 작업이 통째로 버려진다.

모서리 안쪽 바닥이 시각적으로 거슬릴 만큼 넓으면,
**A 를 한 세트(4장)만 적용해 검증한 뒤** 나머지로 확대한다.

## 7. Tile 에셋은 공유된다

`Collider Type` 은 **Tile 에셋 단위**다. 같은 타일을 바닥에도 쓰고 벽에도 쓰면
둘이 같은 설정을 공유한다. 같은 그림을 통과 가능/불가능으로 나눠 쓰려면
**Tile 에셋을 두 개 만들어야 한다** (같은 스프라이트를 참조하는 별개 에셋).
